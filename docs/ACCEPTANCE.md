# 验收标准（非 UI 改动）

> 状态：现行规范（2026-08-01）
> 背景：后续改动集中在数据层 / 索引 / 工具执行 / 推理编排，没有界面可看，
> 实现程度难以评估。本文档定义「可测量、可复现、可自动执行」的验收框架。
> 关联：TODO「Rust 核心与 AI 能力规划」、ADR-0004~0009。

## 1. 验收原则

1. **行为不变优先**：每一步以既有测试（≥191）+ 等价性测试护航，重构不改变
   已验证的行为。
2. **先测量、后定阈值**：任何性能目标先写测量代码跑出现状基线，再按实测
   校准阈值并记录；禁止拍脑袋定数字。
3. **无 UI 也有可观察行为**：通过 API 层测试、数据库内容、导出产物、日志与
   审计记录、索引文件校验来验证，而不是"看起来正常"。
4. **每个条目必须有"先红后绿"的测试**：验收点必须有会失败、实现后才通过的
   测试，不允许只靠人工确认。
5. **数据完整性优先于性能**：迁移、导入导出、流式中断恢复宁可慢、不可错。
6. **逐条可回溯**：每个验收点对应一个测试（命名含验收点编号），PR 描述
   引用验收编号。

## 2. 验收手段（如何评估实现程度）

| 手段 | 用途 | 位置 |
|---|---|---|
| 单元 / 集成测试 | 行为正确性、等价性、错误路径 | Tests/（镜像分层） |
| 合成数据工厂 | 制造规模场景：1 万消息、5 万字长回复、10 万 chunk 资料库 | Tests/Support/ + Tests/Performance/ |
| 性能基线（XCTMeasure + 脚本） | 启动 / 流式存储 / 检索 / 重建吞吐与延迟 | Tests/Performance/ + scripts/ |
| 数据审计 | 数据库内容、导出 JSON 对比、索引文件校验、迁移 fixture | 测试断言 + 复核清单 |
| 静态检查 | 依赖方向、ABI 一致性、工具注册表白名单 | rg / cbindgen --check / 脚本 |
| 代码评审清单 | 安全边界、隐私提示、文档同步等无法自动化的项 | 本文档 §10 |

## 3. 通用质量门（每个条目都必须满足）

- [ ] `swift build` 无警告，`swift test` 全绿且覆盖不降（≥191）
- [ ] `swift-format lint --recursive --strict Sources Tests` 零违规
- [ ] 每个验收点有一个测试（先红后绿），命名可回溯到本文档编号
- [ ] 性能相关改动跑对应基线，无回归（或阈值已校准并记录）
- [ ] CHANGELOG / TODO 勾选与受影响文档同步
- [ ] 数据 schema 变更走 GRDB migration，并有旧库 fixture 升级测试

## 9. 阈值校准流程（先测后定）

1. 每个性能目标先写测量代码，跑出**现状基线**（记录机型 / 数据规模 / release 或 debug）；
2. 设定目标值 = 现状 + 明确期望（如写入量 -50%、p95 < 50ms）；
3. 阈值写入本文档与 CI（XCTMeasure baseline / 脚本断言），避免口头约定；
4. 校准结果记录在 CHANGELOG 或本文档备注，标注日期与测量环境。

## 10. 评审清单（无 UI 复核步骤）

实现完成后，评审人按以下顺序复核，全部通过才算完成：

- [ ] `swift test` 全绿，新验收测试（编号引用）全部通过
- [ ] 性能基准对比记录值，无回归或阈值已校准
- [ ] 迁移验证：旧 schema fixture 数据库升级后数据完整
- [ ] 导入 / 导出等价性验证（前后 JSON 解码相等）
- [ ] 工具注册表白名单检查（无写 / 删工具）
- [ ] 依赖方向检查（rg import，无回环、无越层）
- [ ] 索引文件可重建（删除后 rebuild 恢复）
- [ ] 审计 / 日志输出包含预期记录
- [ ] CHANGELOG / TODO 勾选与文档同步
- [ ] 隐私提示（资料库内容上送 API 的告知）在设置中可见
